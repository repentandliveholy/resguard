Keep your machine responsive under heavy load — without ever freezing an app

resguard is a tiny Rust resource watcher that quietly lowers the priority of heavy batch work — compilers, test runners, build tools, scripts — when your CPU stays saturated, and warns you before memory, swap, or disk space run out. It ships with a ratatui terminal dashboard (rs-tui) and a native desktop app (RS Dash).

Three Ways to Run

Pick the lightweight daemon, the terminal dashboard, or the desktop app — all sharing the same core. Only one governor runs at a time: the TUI and RS Dash attach to the background daemon when it is running.

CLI & Daemon resguard

Runs with minimal overhead (<0.2% CPU). Under sustained CPU load it lowers the priority of heavy command-line work — background QoS (E-cores) on macOS, nice/cgroup weight on Linux, below-normal priority on Windows. RAM, swap, and low-disk guards alert you and name the biggest allocator. It also shows how much CPU comes from processes it can't govern (system services, other users).

Terminal TUI rs-tui

Interactive htop/btop-style dashboard via resguard --tui with live sparklines, a searchable process table, protect list, and threshold editor — it doubles as a control panel for the background daemon.

Desktop App RS Dash

Native Rust eframe/egui GUI with live time-series plots, hover crosshairs, log tailer, and config.toml editor. When the background daemon is running, RS Dash becomes its dashboard instead of starting a second governor.

Safety Guarantees

Design principle: slowing work down is acceptable — freezing it never is.

Never pauses apps by default alert-first

Memory, swap, and low-disk guards send a notification naming the biggest allocator. Pausing is strictly opt-in (--emergency-pause), one process at a time, and auto-resumes after about 20 seconds.

Hands off your apps & system batch work only

Only heavy command-line and batch work is de-prioritized. GUI apps (anything inside a macOS .app bundle), system processes, terminals and shells, and your protected list are never touched.

Every change is reversible ledger

Each priority change is recorded in a ledger and undone on exit, at the next start after a crash, or on demand:

resguard --restore

One governor at a time lock file

A lock file guarantees a single governor. RS Dash and rs-tui act as dashboards and control panels for the background daemon instead of competing with it.

Install as a Background Service launchd · systemd · schtasks

Run resguard automatically on login and restart on updates:

resguard --install-service
resguard --service-status
resguard --uninstall-service

Built-in Update & Auto-Update SHA256 verified

Check or install updates anytime, or let the background daemon keep itself current automatically:

resguard --check-update
resguard --update
# Enabled by default in daemon mode (toggle via --no-auto-update)
